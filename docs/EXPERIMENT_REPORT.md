# 性能实验报告 (EXPERIMENT_REPORT)

> 数据来源：实际运行日志（`results/` 带时间戳目录），**非虚构**。
> 复现：`python -m agent_runtime.cli benchmark --suite main --repeat 5 --seed 42`
> 与 `--suite ablation`。原始数据见 `results/<timestamp>-main/` 与 `results/<timestamp>-ablation/`
> （`config.yaml` / `raw/*.json` / `summary.json` / `report.md`）。

## 1. 实验设置

- 任务：两个相同的多步事实任务序列（便于体现记忆复用）；自动验收。
- 模型：mock-first 确定性 Provider（无 API Key，可复现）。
- 重复：每配置 5 次（随机种子基 42，逐次 +1）；报告均值/标准差/P50/P95（见 summary.json）。
- 环境：Python 3.11.9 / macOS arm64（开发验证）；目标环境 openEuler 24.03-LTS-SP3 见兼容报告。
- 公平性：相同任务、相同 Agent、相同温度/重试/种子，仅通信机制不同。

## 2. 四组主实验（均值）

| 配置 | 成功率 | text_tokens | Token 节省 | 工具调用 | 重复计算降低 | 有效记忆命中率 |
| --- | --- | --- | --- | --- | --- | --- |
| A 文本基线 | 100% | 5106 | 0.0% | 8.0 | 0.0% | 0.00 |
| B 结构化协议 | 100% | 4798 | 6.0% | 8.0 | 0.0% | 0.00 |
| C 结构化 + 非文本状态 | 100% | 760 | **85.1%** | 8.0 | 0.0% | 0.00 |
| D 全系统 | 100% | 760 | **85.1%** | 7.0 | 12.5% | **1.00** |

通信开销：A/B 内联全文（text_chars≈20K/19K，无状态传递）；C/D 引用化（text_chars≈3K，
state_transfers=4，state_bytes≈4144，artifact_refs=4）。

**结论**：
- 结构化协议本身（B）带来约 6% token 节省（短键、去冗余）。
- 非文本状态 + Artifact 引用（C）是 token 节省主因，达 **85%**，且成功率保持 100%。
- 全系统（D）在 C 基础上引入共享记忆：第二个相同任务被有效复用（有效记忆命中率 1.00），
  工具调用由 8 降到 7（重复计算降低 12.5%）。

## 3. 消融实验（隔离各机制贡献）

| 配置 | Token 节省 | 重复计算降低 | 有效记忆命中率 | 说明 |
| --- | --- | --- | --- | --- |
| D 全系统 | 85.1% | 12.5% | 1.00 | 基准 |
| D − 共享记忆 | 85.1% | 0.0% | 0.00 | 失去复用 → 重复计算降低归零 |
| D − 非文本状态 | 6.0% | 12.5% | 1.00 | 失去引用化 → token 节省退回结构化协议水平 |
| D − CodeAct 沙箱 | 85.1% | 12.5% | 1.00 | 通信/记忆收益不变（沙箱主要影响时延，见下） |

**结论**：token 节省主要由「非文本状态 + 引用」贡献；重复计算降低主要由「共享记忆」贡献。
两者正交、可叠加。

## 4. 时延与资源（诚实记录的权衡）

- 通信时延：C 相对 A 略有改善（约 +5%）；结构化与引用降低了序列化/搬运成本。
- **CodeAct 沙箱的时延代价**：D 引入子进程沙箱执行，端到端时延显著高于 A（subprocess 启动开销，
  约 1ms → 17ms 量级）。这是「安全隔离换时延」的**真实权衡**，并非缺陷：
  - D − CodeAct 沙箱 配置的时延回落到与 B 同级，验证时延回归来自沙箱而非协议；
  - 生产中可按需启用沙箱（仅对不可信代码），或使用常驻 worker 摊薄启动开销（未来工作）。
- RSS 峰值：各配置 51–54 MB，10 轮连续运行无明显增长（见稳定性测试）。

## 5. 派生指标定义与取值

- Token 节省率 = 1 − tokens(cfg)/tokens(A)：C/D ≈ 0.851。
- 重复计算降低率 = 1 − tool_calls(cfg)/tool_calls(A)：D ≈ 0.125。
- 有效记忆命中率 = Effective / Used：D = 1.00（无负迁移 Harmful=0）。
- 成功率：全部配置 100%（未以准确率换 token）。

## 6. 关联连续任务（记忆复用的强证据）

任务组 A（相似缺陷修复）与 B（重复工程改造）见 `tests/integration/test_scenarios.py`：
- A2 / B2 **不提供修复/改造策略**，仅当复用 A1 / B1 沉淀的过程性记忆时才能通过沙箱验收；
- 无记忆时 A2 / B2 失败（`test_group_a_fails_without_memory_reuse`）。

这直接证明共享记忆带来了**跨任务可迁移的能力**，而非仅仅缓存数值。

## 7. 局限与说明

- 当前主实验使用 mock LLM 以保证可复现；真实 LLM 下绝对数值会变化，但机制带来的相对收益方向一致。
- 开发验证在 macOS；openEuler 目标环境验证见 `docs/OPEN_EULER_COMPATIBILITY.md`（用户在 VM 执行 verify 脚本）。
- 所有数值来自 `results/` 原始文件，可独立复核。
