# 已知限制与未来工作 (LIMITATIONS & FUTURE WORK)

## 已知限制

1. **mock-first 实验**：主实验使用确定性 mock LLM 以保证可复现；真实 LLM 下绝对数值会变化
   （相对收益方向一致）。已提供 OpenAI 兼容适配器供复测。
2. **CodeAct 沙箱时延**：子进程隔离带来真实启动开销，D 配置端到端时延高于基线（消融已定位来源）。
3. **网络隔离强度**：subprocess 后端对网络仅为最佳努力（清代理 + 环境标记）；强隔离依赖 openEuler 上
   namespace / Podman（`--network=none`）。
4. **任务域**：演示场景为可自动验收的「软件仓库维护」（求和任务 + 代码修复/改造），策略以受控正则变换实现；
   尚未覆盖大型真实仓库的复杂补丁。
5. **目标环境验证**：开发与自测在 macOS/Windows 进行；openEuler 24.03-LTS-SP3 实测需用户在 VM 执行
   `verify_openeuler.sh` 并回填兼容报告。
6. **向量规模**：默认 numpy 暴力检索适用于中小规模；超大规模需切换 hnswlib/faiss。

## 未来工作

1. **常驻沙箱 worker**：以进程池/预热容器摊薄 CodeAct 启动开销，降低时延。
2. **真实 LLM 大规模评测**：接入云端模型，扩展任务集，给出带置信区间的收益。
3. **更强状态表示**：引入隐藏状态特征/KV 重用、AST/调用图引用，进一步减少文本与重复推理。
4. **eBPF 可观测增强**：内核态采集 IPC/系统调用指标（后期可选，不在关键路径）。
5. **记忆治理**：TTL/容量淘汰、跨会话持久化与冲突合并、更精细的负迁移检测。
6. **协议序列化对照**：补齐 MessagePack/Protobuf 的端到端对照实验。
7. **分布式运行时**：跨主机 UDS→TCP/QUIC、多节点调度与容错。
