# 重大设计决策记录 (DECISIONS / ADR)

> 格式：编号 / 日期 / 决策 / 背景 / 备选 / 结论 / 影响。

## ADR-0001 mock-first Provider 策略
- **日期**：2026-06-25
- **决策**：所有 LLM/embedding 调用走统一 `providers` 抽象，默认确定性 mock，无需 API Key 即可运行全部测试与实验；OpenAI 兼容适配器为可选。
- **背景**：赛题要求无 Key 时仍可运行测试；实验需可复现、不虚构。
- **备选**：强制真实 LLM（不可复现、CI 需密钥）。
- **结论**：mock-first。
- **影响**：实验确定性强；真实 LLM 作为补充验证。

## ADR-0002 向量后端可插拔，默认 numpy
- **日期**：2026-06-25
- **决策**：默认 hash-mock embedding + numpy 暴力检索；可切 sentence-transformers / hnswlib / FAISS。
- **背景**：纯软件 CPU 约束，避免重依赖导致 openEuler 安装失败。
- **结论**：numpy 默认，重后端可选。
- **影响**：开箱即用；规模大时可升级索引。

## ADR-0003 通信传输：进程内队列 + 可选 UDS + shared_memory
- **日期**：2026-06-25
- **决策**：默认进程内异步队列（可移植、可测）；UDS 作为系统层 IPC 证据；大向量用 `multiprocessing.shared_memory` 零拷贝传输。
- **背景**：既要体现「系统层机制」，又要保证跨平台可测与可复现。
- **备选**：纯内存对象传引用（系统层说服力弱）。
- **结论**：双实现 + 共享内存。
- **影响**：架构更复杂但得分更高，且可降级。

## ADR-0004 沙箱分层与降级
- **日期**：2026-06-25
- **决策**：基础 subprocess+timeout+`resource.setrlimit`；openEuler 增强 cgroup v2 + namespace；Podman/bubblewrap/seccomp 可选；能力不可用时自动降级。
- **背景**：跨平台 + 安全隔离需求。
- **结论**：能力探测 + 降级链。
- **影响**：在任意环境可运行，openEuler 上启用更强隔离。

## ADR-0005 双模式公平性：单一协议真源 + 映射器
- **日期**：2026-06-25
- **决策**：Pydantic `AgentMessage` 为唯一真源；`text_mode` 由映射器把同一消息渲染为自然语言文本透传，逻辑/Agent/工具/温度/重试/种子完全一致。
- **背景**：通信效率对比必须公平。
- **结论**：同源映射 + 等价性断言。
- **影响**：消除「实现差异」干扰，对比只反映通信载体差异。

## ADR-0006 Python 版本策略
- **日期**：2026-06-25
- **决策**：`requires-python >= 3.10`，工具 target 3.10；统一 `from __future__ import annotations`；避免 3.11+ 专属语法。openEuler 24.03-LTS-SP3 自带 Python（通常 3.11）以实际为准并在目标环境验证。
- **背景**：开发机/目标环境版本可能不同。
- **结论**：兼容 3.10+。
- **影响**：跨环境可运行。

## ADR-0007 实验数据不可覆盖
- **日期**：2026-06-25
- **决策**：实验结果落 `results/<timestamp>-<config_hash>/`，保存配置快照、原始日志与聚合；禁止覆盖。
- **背景**：禁止虚构、需留痕。
- **结论**：时间戳目录 + 配置快照。
- **影响**：可追溯、可复现。

## ADR-0008 开发平台与目标平台分离
- **日期**：2026-06-25
- **决策**：开发在 Windows 进行，最终目标 openEuler 24.03-LTS-SP3 (x86_64)。代码保持跨平台，系统增强能力（cgroup/namespace/Podman/UDS）在不支持平台自动降级。区分「开发环境验证」与「目标环境验证」。
- **背景**：用户明确开发不在 macOS，且不需过度纠结 macOS 移植。
- **结论**：跨平台 + 能力探测降级。
- **影响**：Windows 可开发自测，openEuler 上启用完整能力并做最终验证。
